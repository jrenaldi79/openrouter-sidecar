**Owns:**

- Configuration: `settings.py` (`SlackSettings`, `load_slack_settings`; off unless `SIDECAR_SLACK_ENABLED` is set, then both tokens are required and their prefixes checked). `HostedSettings.slack` carries the result.
- Slack I/O seam: `api.py` (`SlackApi` protocol, `SdkSlackApi` over slack_sdk's async client, `SlackMessage`/`SlackFile`/`Page`, `SlackCallError` with `retry_after_s`). Nothing else in the bot talks to Slack; tests use `FakeSlack` from `tests/slack_fakes.py`, which must keep the protocol's signatures.
- Channel registry: `registry.py` (`ChannelRegistry` over the `slack_channels` table, `ChannelRow`, `new_row`, `DEFAULT_ALIASES`). One row per (Slack team, channel); `deactivate`, `mark_welcomed` and `mark_warned` are guarded updates that return True only for the caller that changed the row.
- Team identity and credentials: `principal.py` (`team_principal` builds the `slack|<team>:<channel>` principal only from the signed event's ids plus an active registry row; `acting_as` sets a module-private context variable and always resets it; `SlackCredentials` is the `CredentialSource` for the team in context). Team keys are created by `KeyProvisioner.ensure(principal, team=TeamKey(label))`, named `Sidecar · <label> · <cohort>` and budgeted by the `Sidecar team budget` guardrail (no guardrail, no key). A Slack principal without `team`, or a student with one, is refused.
- Job queries: `jobs.py` (`SlackJobs` over the Slack columns that `advisor_results.py` adds to `advisor_jobs`: `spend_by_user`, `spend_since`, `running`, `mark_posted`, and `orphans` for restart recovery). Per-team caps reach `Limits.admit(scope, max_concurrent=, daily_usd=)` from the registry row; the per-Slack-user request window is `Limits.window(...)`, independent of the per-minute budget.
- Command parsing: `parser.py` (pure, no I/O, no imports from the other Slack modules). `command_text` turns a mention's raw text into the words to parse (decodes `&amp; &lt; &gt;`, unwraps links, finds the first `<@BOT>` anywhere); `parse` turns those words into an `Intent` (`Ask`, `Compare`, `Models`, `SetDefault`, `Usage`, `Remember`, `Recall`, `Forget`, `Help`, `ThreadCommand`, `Empty`); `wants_sandbox` decides sandbox mode. Anything that is not an exact command form is a question, and unknown aliases are left for the dispatcher to validate.
- Replies: `replies.py` (everything about how Sidecar's text reaches Slack). `escape` turns `&`, `<`, `>` into entities so model output can't form mentions or disguised links; `clean` is redact, then mask the caller's secrets with `***`, then escape. `split_answer` cuts at 3,500 characters on paragraph boundaries (`"".join` gives the original back; one oversized paragraph is hard-cut; empty text gives `[]`); the caller posts a Markdown file instead when there are more than `MAX_PARTS` parts. Plain-text `footer`, `limit_text`, `budget_text` and `provider_error_text` hold the copy. `WorkingMessage` is the one progress message per model: `step` edits only on a changed text at most every 10 seconds and drops the rest, `finish` always edits, and `start`, `step` and `finish` all run their text through `escape` (a step can carry model-chosen words, so callers pass raw text, not `clean` output), and neither raises on `SlackCallError`. `post_answer(api, channel, thread_ts, label, text, footer, *, secrets=())` is the one final post (the runner now, restart recovery later): `clean`, `split_answer`, up to `MAX_PARTS` messages as `Sidecar · <label>` with the escaped footer on the last, more as one `answer.md` upload (redacted and masked, not escaped) plus the footer; each Slack call is retried once (honouring `retry_after_s` up to 5 seconds), so no part posts twice, and a second `SlackCallError` propagates. `key_text(error)` is the team-facing copy for key problems: the provisioning messages (`NOT_READY`, `DISABLED`, `UNAVAILABLE`, `KEY_REJECTED`) speak to one student, so Slack never shows them.
- Thread map: `threads.py` (`ThreadMap` over `slack_threads`, `ThreadChat`). Key is `(channel_id, thread_ts, alias, mode)` per team scope, unique among unarchived rows, so a thread can hold an inline and a sandbox chat for one model. `put` replaces an unarchived row's chat and clears its seen/answered marks; `seen` only moves `last_seen_ts` forward (numeric compare, original string kept); `answered` stamps the chat, and `last_answered` (never archived or unanswered rows) says which chat a follow-up continues; `archive` is `!restart`.
- Channel memory: `memory.py` (`ChannelMemory` over `slack_memory`, `MAX_NOTES = 50`, `MAX_CHARS = 8000`, `MEMORY_PREFACE`). Notes are numbered by insertion order and renumber after `forget`; `add` counts the new note against both caps; `instructions` is `""` or the preface plus numbered notes, added to each request.
- Student copy: `welcome.py` (`welcome_text(row, budget_usd)` is the one-time welcome, its example alias `gemini` when the row has it and the channel default otherwise; `help_text(row)` lists aliases (sorted), the default, the Fusion panel and analyst, every command and `DATA_NOTICE` under "What I send and keep", and is entity-escaped once at the end; `NOT_SET_UP` and `GUEST_OFF` are the one-line off states). Plain text only, our own words, never model output.
- Guests and shared channels: `guests.py` (`channel_problem(api, channel_id)` returns `"shared outside the organization"` for `is_ext_shared` or `is_pending_ext_shared` (checked first, no member scan), `"has a guest member"` when any member is `is_restricted` or `is_ultra_restricted`, else None; the ops script will call it before `add` and `update --active`, but does not exist yet). `GuestGuard` deactivates a registered channel on `on_member_joined` (guest) or `on_channel_shared`, posting `GUEST_OFF` at the top level only when `deactivate` returns True, so once. `allowed(row)` re-reads the row first (missing or inactive is False with no Slack call), re-checks members at most every `every_s` (default one hour, last success cached in memory per channel), and when the check fails for any reason fails open only within `2 * every_s` of the last success, never records a success on failure, and retries next call. A failed `users.info` on a join marks the channel for re-check: `allowed` then bypasses the cache and denies on any failure until a check succeeds. Events for unregistered channels are ignored.
- Context builder: `context.py` (`ContextBuilder`, `NameCache`, `format_message`, `Gathered`, `Context`) and `context_files.py` (`trigger_files`, `safe_name`). `gather(channel, thread_ts, trigger, first_turn=)` reads the thread once (at most 10 pages of 200, the trigger added and deduped by ts, join/leave dropped; a failed read raises) and, on a first turn only, pins and up to 20 channel messages before the root (top-level only; a Slack error on pins or history is logged and that part is left out). `render(g, since_ts)` builds `Context.text` as `DATA_PREFACE` plus headed sections (pins capped at `PINS_CHARS`, channel at `channel_chars`, thread at `THREAD_CHARS`, always the newest kept, a thread keeps its root and a trimmed-messages note); later turns render only thread messages newer than `since_ts`. Lines are `[Oct 20 10:14] Name: text` in America/Chicago (day unpadded, no `%-d`, so it works on Windows; `tzdata` is a dependency for that reason). Names: humans via `NameCache` (display name, real name, id; a failed lookup returns the id and is retried after 60 seconds); a bot post shows its label, `claude` in any case as `Claude`, no label as `bot`. Message bodies get only Slack's three entities decoded (`parser.decode_entities`, `&amp;` last; `&region=us` stays), continuation lines are indented two spaces and names lose control characters, so a body cannot forge a `[time] Name:` line or a section header. `Context.urls` is every http(s) link in the whole gathered thread and trigger (the web_fetch allowlist), on later turns too. Only the trigger's text attachments become `slack/files/<safe name>` packets (download capped at four bytes per allowed character, strict UTF-8 with no NUL, duplicates suffixed `-2`, total within `files(trigger, budget=)`, default `MAX_SESSION_CHARS` minus the largest `context.md` this builder renders; the runner may pass less); anything unreadable, too long, over budget or non-text is listed by name, as are files elsewhere in the thread. `<@U...>` markup stays in message text.
- Channel function tools: `slack_tools.py` (`ChannelTools(api, names, channel_id, thread_ts)`, `TOOL_SPECS`, `FUNCTION_NAMES`; the tool loop calls `await tools.call(name, arguments_json)` and gets `(output, step label)`). `read_thread(thread_ts?, before?, limit?)`, `read_channel_history(before?, limit?)` and `search_channel(query, limit?)` always use the job's channel: specs carry no channel argument and unknown keys (a forged `channel`) are ignored. A `ts` argument must fully match `[0-9]{1,12}\.[0-9]{1,8}` (ASCII digits only) (`bad timestamp`); arguments that are not a JSON object give `bad arguments`; a non-integer `limit` falls back to the default (50 reads, 20 search) and integers clamp to 1..200. Output is `DATA_PREFACE` plus `format_message` lines oldest first (names resolved like `ContextBuilder`; bot posts keep their label), the newest kept within `CHARS_CAP` (30,000), then a footer when messages were left out (the count, "at least" when pages were unread, and the oldest shown ts as `before` to continue; `read_thread` also names a non-current `thread_ts`); no messages gives `No messages found.`. A thread is read through at most 10 pages of 200 (a note says when it was longer). Channel history reads drop join/leave and thread replies (`is_channel_message`). Search pages newest-first (at most `SEARCH_PAGES` pages and `SEARCH_MESSAGES` messages), matches when every whitespace-separated term is in the entity-decoded text, case-insensitive, and reports how many messages it searched (matches cut by `limit` and by the size cap are reported separately, since raising `limit` cannot undo the cap) and, if older ones were not, the `read_channel_history` `before` to go further. Failures never raise: a `SlackCallError` gives `Error: Slack said <code>`, any other exception `Error: <type name>`, both labelled `Tool error` and logged through the redacting logger. Step labels are short and plain (`Read 60 earlier messages`, `Read the thread`, `Searched the channel for 'x'`, query clipped to 40 characters). No `strict` on the specs.
- Job payload: `payload.py` (`build_slack_payload(chat, brief, files, uploads, *, row, domains, memory_text, compare, listed=())` starts from `advisor_payload.build_payload`, then sets `store: False` (never `previous_response_id`; the tool loop replays output items), Slack instructions (`SLACK_INLINE`, `SLACK_SANDBOX`, `SLACK_COMPARE`: data rule, tools actually present, a generic web_fetch line (no domain, host or file name from Slack ever goes into instructions; domains travel only as tool parameters), and for sandbox the outputs rule plus `advisor_payload.SANDBOX_SAFETY` and `upload_notes(uploads)`, so the bundle paths and container rules match `build_payload`; compare describes the panel, not tools the outer model lacks) plus `memory_text` after a blank line, and for an ask `tools = TOOL_SPECS + server_tools(...) + shell` with `max_tool_calls` 12 inline or 24 sandbox. `compare` ignores sandbox: `FUSION_FORCED = True` sends `openrouter:fusion` alone with `tool_choice` `FUSION_CHOICE`; False uses model `openrouter/fusion` with a `plugins` entry carrying the same panel, analyst and tools. The live spike (`tests/live/test_slack_spikes.py`) decides the constant. `fetch_domains(urls, allowlist)` keeps public hosts only (`urls` need an http(s) scheme; an allowlist entry may be a bare domain but not another scheme; userinfo, port and trailing dot dropped; lowercased; IDNA-encoded; IP literals, `localhost`, dotless and shorthand-IP hosts, backslash-netloc URLs, non-strings, `SHARED_SUFFIXES` such as `github.io` and registry suffixes such as `co.uk` dropped, while `alice.github.io` stays; allowlist entries take slots first, thread hosts fill the rest of 20; sorted) and never raises. The web_fetch rule is one function: with no domains there is no `openrouter:web_fetch` at the top level, in the `helper` subagent or in Fusion `tools`. `files_note(listed)` is `""` or `Files in the thread, not attached:` plus one one-line name per line; the payload appends it to the brief, not the instructions, because the names come from Slack.)
- Sandbox outputs: `outputs.py` (`MAX_FILES = 5`, `MAX_BYTES = 20 MB`, `OutputRef(file_id, path)`, `output_refs`, `Outputs(api).post(client, key, channel, thread_ts, label, container_id, refs)`). `output_refs(items, container_id)` reads `files` from `openrouter:shell` and `shell_call_output` items only; an entry counts when it is a dict with string `container_id`, `file_id` and `filename`, and its `container_id` is the chat's. `filename` is normalized from `/workspace/project/<rel>`, `project/<rel>` or a bare `<rel>`, and kept only when `<rel>` is `outputs/` plus at least one segment (no backslash, no character of Unicode category Cc, Cf, Zl or Zp such as C1 controls, bidi overrides, zero-width characters and U+2028, no empty, whitespace-only, `.` or `..` segment, and no other absolute path). Dedupe is by `file_id`, the latest path wins, order is first appearance. `post` downloads each ref with `AdvisorClient.container_file` (the team key; `max_bytes` is the remaining budget of 20 MB, so a later small file can still fit) and uploads it as `Sidecar · <label>` with the name `<path under outputs/>` with `/` as `_`, at most 200 characters, extension kept (also the title). More than five files, a file over the budget (`ContainerFileTooLargeError` from the client: "it would take this answer past 20 MB of files"), a download error and an upload error each give one note naming the file (plain copy, never ids, keys or error text). At most 10 per-file notes are posted, then one line "…and K more files weren't posted."; three consecutive download failures (oversize and upload failures don't count, a success resets the streak) stop further downloads and the rest count toward K. Notes go out as one escaped message in the thread, and `post` never raises.
- Usage report and budget warning: `usage.py` (`UsageReport`, `usage_report(key_info, jobs, scope, row, names, now)`, `usage_text(r)`, `budget_warning(r, row, month, registry)`, `WARN_AT = 0.8`, `MAX_USERS = 10`, `month_key(now)`, `budget_report(key_info)`, `answer_warning(...)`). Month spend and budget come from `GET /key` (`usage_monthly`, `effective_budget.limit_usd`); a missing, non-positive or non-numeric limit means no budget (`budget_usd` and `remaining` None, "no monthly limit set", never a warning) and a non-numeric spend counts as 0, so odd key info never raises. Today's spend is `spend_since` from the UTC date, the same boundary `Limits.admit` uses for the daily cap; the breakdown is `spend_by_user` since the first of the UTC month, only the top ten are named, through `NameCache` (`context.one_line`: one line, control characters stripped, id when empty, then `replies.escape`), largest first, then "...and K others" from `UsageReport.others`. All job queries use the team scope. `usage_text` is plain team copy with dollars as `$1.23` and no key, hash, label or other key field; it is safe to post as is, because `usage_report` escapes the Slack-sourced names (`commands.py` posts it for `@sidecar usage`). `budget_warning` needs `month_spend / budget >= WARN_AT` and then `mark_warned(team, channel, month)` to return True (the first claim of the UTC `YYYY-MM` wins), and gives "This team has used N% of this month's Sidecar budget." with N floored. The runner calls `answer_warning` only when an answer is about to post (not for failed, stopped or interrupted jobs), and it returns None without fetching when the job's row already shows this month's `warned_month`; otherwise it fetches key info through `SlackRunner.key_info` (default `openrouter_keys.current_key`, called with the team key, bounded by `WARN_FETCH_S = 4.0`; a timeout means no warning), builds the cheap `budget_report` (no job queries or Slack lookups) and `footer` appends the warning as a line after the footer; with no `registry` on the runner, or on any exception (logged by type only), the answer posts with no warning. The claim comes before the post, so a post that then fails twice loses that month's warning.
- Job runner: `runner.py` (`SlackRunner`, `SlackServices`, `SlackJob`, `QUEUE_WAIT_S = 120`, `HEARTBEAT_S = 10`, `CHAT_BUSY`), `runner_queue.py` (`Entry`, `Shared`, `wait_turn`), `runner_turn.py` (`Turn`: one admitted job's files, payload, tool loop, answer, ending and job-row writes) and `runner_steps.py` (pure: `step_label`, `panel_failure`, `trim_files`, `failure_text`, `ChatFullError`, `MODERATED`). `run(services, job)` runs inside `acting_as(job.principal)` and takes key and scope from the cohort's credential source. Queue, all by one `QUEUE_WAIT_S` deadline: the chat's FIFO `asyncio.Lock` first, then a team slot (`asyncio.Semaphore(max(1, row.max_concurrent))` per owner; a cap below 1 then fails `Limits.admit` with the concurrency copy), so a waiting follow-up never holds a slot another chat could use and same-chat asks run in arrival order; a chat wait that runs out says `CHAT_BUSY`, a slot wait the concurrency `limit_text`. `Shared` drops a lock or semaphore when its last job ends (no unbounded growth; a changed `max_concurrent` applies once the team is idle). `wait_turn` also ends when the job is stopped, and a stopped job says "Stopped." without reaching `Limits.admit`. Then `Limits.admit` with the row's caps, and a poll every `IDLE_POLL_S` until `active_for_chat` is empty and `results.create` succeeds (the cross-process check, Review Focus 3). Then `WorkingMessage.start`; the work (`Turn.work`) runs in its own task under a heartbeat that refreshes `heartbeat_until` every `HEARTBEAT_S` and, if the key or lease is lost, cancels only that task (an "Interrupted. Ask again." ending; `run` returns); any other heartbeat error is logged by type and ends the beat. The heartbeat is stopped before the outcome is handled, so no tick can race an ending; a cancellation of `run` itself interrupts the row and propagates. Interrupted rows keep the loop's spend so far (the loop attaches it to the cancellation), and an upload-cleanup error while cancelling is logged, not raised, so it can't turn a cancel into a provider failure. The work: status `running` with `slack_working_ts`; the trigger files trimmed to the chat's session room (`MAX_SESSION_CHARS` minus the new context file and the stored files that stay; overflow names join `listed`) and upserted with `slack/context.md`, which is replaced, never added (a session still too full is `ChatFullError`); `AdvisorService._prepare` (redacts the brief, refuses the key in files), the history cap (`ChatFullError` asks for `!restart`), upload cleanup, and for sandbox chats that are not compares `_sandbox_uploads`; `build_slack_payload(..., listed=)`, `configure_cache`, `run_tool_loop` with `ChannelTools` (empty for compare) whose labels and server items (`step_label`) become progress steps (`Tool error` is not one); `_check_container` over every round's items for sandbox chats, then `_answer`; a compare whose Fusion item shows every panelist failed answers "Every model in the panel failed: …". `append_turn` stores the plain redacted brief (not the file notes), then the row completes with the loop's cost. Delivery: `post_answer`, then `mark_posted` at once (recovery never posts twice), then `Outputs.post` for sandbox chats that are not compares (`output_refs(turn.items, chat.container_id)`; never fails the answer), then `answered` and `seen(newest_ts)`; a failure in `mark_posted`, `answered` or `seen` is logged by type and "Sidecar · <label> answered below."; a second post failure leaves `slack_posted_at` NULL and says so in the working message. Errors: the row is failed with the spend already made (the loop's partial cost on a mid-loop error, the whole loop's cost when the answer fails after it), and `failure_text` maps `RateLimitedError` to `limit_text`, 402/403 (`InsufficientCreditsError`, `ForbiddenError`) to `budget_text`, `ModerationError` to `MODERATED` (its row error is a fixed "Blocked by provider moderation.", since the message quotes the flagged input), key errors to `key_text`, `ChatFullError` to its restart copy, other `OpenRouterError`s to `provider_error_text` naming the other aliases, anything else to a generic line (never the error text). `stop(owner, channel_id, thread_ts)` flags the thread's queued and running jobs (a running one stops before its next model request) and returns the count; a stopped job records the loop's partial cost, is interrupted with "Stopped from Slack", discards its answer, stores no turn and says "Stopped.". `running(owner, channel_id, thread_ts=None)` lists queued and running labels. All queue state is in memory: one owner replica runs Slack jobs. `clock` paces progress edits only.
- Request flow: `dispatch.py` (`Dispatcher(deps, *, bot_user_id)`, `Deps`, `ONLY_SOME`, `KEY_PROBLEM`, `FAILED`), `commands.py` (`Turn`, `run_command`, `static_text`, `resolve_alias`, `UnknownAlias`, `unknown_alias_text`) and `asks.py` (`prepare_jobs`, `COMPARE_ALIAS`, `SANDBOX_OFF`, `START_FAILED`, `READ_FAILED`). `on_mention(team_id, event)` never raises (one outer try logs any failure by type, so a malformed event or a storage error can't stop the gateway). It ignores edits (`edited`), `message_changed`/`message_deleted` subtypes and any post with a `bot_id`, and any event unless team, `channel`, `user` and `ts` are non-empty strings (and the user is not the bot itself), then: gate (unregistered gives `NOT_SET_UP`; inactive is silent; a user outside a non-empty `invoker_allowlist` gets `ONLY_SOME`; `GuestGuard.allowed` false is silent), the welcome once through `mark_welcomed` (no budget figure: no key yet), `parse(command_text(...))`, the per-user window `slack-user|<team>|<user>` (`settings.user_limit` per 600 s, `limit_text` on a hit; thread commands, help and an empty mention don't count, asks and the other commands do), help and an empty mention from the row alone (`static_text`, no key needed), `KeyProvisioner.ensure(principal, team=TeamKey(label))`, then everything else inside `acting_as(principal)` with the scope from the cohort's credentials (`deps.services[row.cohort]`). The principal comes only from the event's team and channel plus the registry row. Replies go in `thread_ts`, else under the mention, as `Sidecar`; key problems use `key_text` for the known provisioning messages and `KEY_PROBLEM` otherwise, any other failure `FAILED` (logged by type, never the error text). `run_command` returns post-ready text (memory notes, aliases, model names and labels escaped once; `help_text` and `usage_text` returned as they are): `models` resolves every alias now, `set default` must name an alias of `alias_map` and persists through `ChannelRegistry.update`, `usage` fetches `GET /key` through `runner.key_info` (bounded by `USAGE_FETCH_S`, any failure says try again) and `usage_report` with `runner.names`, memory commands map `BadRequestError` to its message, `!restart` archives the thread, `!stop` flags the thread's jobs, `!status` lists the thread's labels (the channel's at the top level, where the trigger ts is the reply ts). `resolve_alias(row, alias, preferences)` goes through `alias_map` then `PreferenceService.resolve`; the label is the brand, else the catalog name; an unmapped alias without `/`, or an exact id the catalog refuses, raises `UnknownAlias(valid)`. `prepare_jobs` picks the models (named aliases; else the alias of `threads.last_answered`, else `default_model`; a plain follow-up to a compare is a compare), the mode per alias (`sandbox` when `wants_sandbox`, else that alias's last mode in the thread, else `inline`; always `inline`, plus the `SANDBOX_OFF` line, when `sandbox_enabled` is false), gathers with `first_turn=True` and renders with `since_ts=None` once for every model and turn, `fetch_domains(context.urls, row.fetch_allowlist)`, then finds or starts each chat (`threads.get`, else `advisors.start(model, title, sandbox=)` and `threads.put`) under a per-(owner, workspace, channel, thread, alias, mode) `asyncio.Lock` from `Deps.chat_locks` (a `runner_queue.Shared`, dropped when idle), so racing first mentions share one chat. A compare is one Fusion job: label `Fusion`, thread key `COMPARE_ALIAS`, outer chat on `fusion_analyst`, never sandbox. One model failing to resolve or start says `provider_error_text` and the others still run; a `put` failure says `START_FAILED`; a failed thread read `READ_FAILED`. Each job runs as an `asyncio` task created with a copy of the context, held in a set until done; an exception is logged by type. `drain()` waits for them.
- Gateway: `gateway.py` (`Gateway(app_token, web_client, dispatcher, guard, registry, events, *, bot_user_id, client_factory=SocketModeClient, purge_interval_s=3600)`, `EventLog`). `start()` returns at once: it builds the client with `app_token=` and `web_client=`, adds `on_request` to `socket_mode_request_listeners`, and runs `connect()` as a task the gateway holds (the real `connect()` retries forever on a bad token or an outage; a connect error is logged by type), plus the purge loop (`events.purge` at start and then every interval; a failed purge is logged by type). So the owner-lock gain hook can await `start()` safely. A second `start()` while started is a logged no-op; `start()` after `stop()` works again. `stop()` is idempotent and safe before `start`: it sets `_stopping` first (`on_request` still acks but drops every envelope, including one that arrives while the database call runs), then `client.close()` (which turns off auto-reconnect and disconnects; `disconnect()` alone would let the SDK reconnect mid-drain), cancels the connect and purge tasks, and waits up to `grace_s` (5 s) for handler tasks before cancelling the rest; a failing step is logged and the next still runs. `on_request` acks first with `SocketModeResponse`, always, even for dropped or invalid envelopes (an ack failure is logged and handling goes on), then ignores anything but `events_api`, drops a payload whose `event_id` or `team_id` is not a non-empty string or whose `event` is not a dict, dedupes, and drops events with a `bot_id`, `edited`, or a `bot_message`, `message_changed` or `message_deleted` subtype. Dedupe runs before the filter. It checks a bounded in-memory set of the last 1,000 ids first (a repeat is dropped even while the database is down, and racing repeats in one process lose), then `EventLog.first_time(event_id)`: `INSERT ... ON CONFLICT DO NOTHING` on `slack_events(event_id, received_at)` with `rowcount == 1` meaning first, so two replicas on one database handle an event once. `purge(now, older_than_s=86400)` deletes older ids and returns the count. A database error is logged by type and the event is handled anyway (only the owner replica runs the gateway, so a lost mention costs more than a rare repeat). Routing: `app_mention` to `Dispatcher.on_mention`, `member_joined_channel` to `GuestGuard.on_member_joined`, `channel_shared` to `on_channel_shared`, and `member_left_channel` by the bot or `channel_left` (what Slack sends the bot itself) to `ChannelRegistry.deactivate(team, channel, "bot removed")`; other types, and routed events missing their channel or user, are ignored. Each handler runs as a task in `_tasks` (removed when done) so `on_request` returns fast; an exception is logged by type through `redact_log`, never its message. Task 21 starts and stops it from the owner lock hooks.

**Invariants:**

- Identity comes only from the signed Slack event, never from message text or a caller-chosen field.
- Every query binds both the owner and the workspace. The one exception is `SlackJobs.orphans`, a server-side restart sweep filtered by `slack_channel_id` and `process_id`; its caller must act on each row under that row's own team principal.
- Slack never calls `AdvisorService.send`.
- `SLACK_BOT_TOKEN` (`xoxb-`) and `SLACK_APP_TOKEN` (`xapp-`) come only from the environment, stay out of `repr`, and are masked by `logs.redact`. The secret scan blocks literals.

Dispatch tests use `tests/slack_dispatch_rig.py` (`DispatchRig`: the runner rig plus a registered row, `GuestGuard`, a real `ContextBuilder`, `FakePreferences` over a fixed catalog, `FakeProvisioner`, and `mention(text)` that feeds an `app_mention` and drains the jobs). Gateway tests (`test_hosted_slack_gateway.py` for routing, dedupe and purge, `..._lifecycle.py` for start and stop) use `tests/slack_gateway_rig.py`: `FakeClient` (the `SocketModeClient` surface; `deliver` plays a reconnected socket, `connect_forever` and `on_close` stage hangs and late envelopes), a `Recorder` for the handlers and `Rig`. Build token fixtures at runtime (`"xoxb-" + "7" * 20`); the secret scan covers tests.
