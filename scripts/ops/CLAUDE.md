**Owns:**

- `real_login.py`: the authorization-code + PKCE flow an MCP client runs, using the shared public client "MPD MCP Clients" and its registered `http://localhost:33418/callback`. Saves the access token to `.dev-state/real-token` (mode 600) and prints only the audience, permissions and whether the profile claim is present. `--prompt-login` forces the account chooser.
- `acceptance_probe.py`: checks a deployment with that token: 401 without a token, admission (403 means the account lacks `sidecar:use` or the profile claim), the hosted tool surface, `account_status` (which issues the signed-in account's own key on first use), and an image upload and download (proves the asset volume is writable). `--expect-forbidden` checks only that an account without access is refused.
- `openrouter_keys.py`: the instructor's key manager for students' and Slack teams' keys (`list`, `show`, `disable`, `enable`, `delete --yes`, `usage --csv`, `guardrails`) over the server's own seam (`hosted/openrouter_keys.py`). `list` and `usage` cover each cohort's student workspace and the Slack workspace (`config.SLACK_WORKSPACE`, group `slack`; `--cohort slack` limits a command to it, and a team is matched by its label where a student is by email; `usage` sums the Slack workspace per class, `slack (2027): N keys, ...`, and its CSV has `cohort` (the class: the last part of a team key's name) then `group` (a cohort year or `slack`)); `guardrails` checks `Sidecar student budget` in each cohort workspace and `Sidecar team budget` in the Slack workspace. Reads `OPENROUTER_MANAGEMENT_KEY` from the environment. `delete` is a reset (the student gets a fresh key on the next call); `disable` blocks.
- `slack_channels.py`: the instructor's Slack channel registry (`add`, `update <label> [--active]`, `deactivate <label> --reason`, `list`) over `ChannelRegistry`. `add` and `update --active` call `channel_problem` with an `SdkSlackApi` on `SLACK_BOT_TOKEN` and refuse with its reason (a guest member or an outside-shared channel). `--default-model` is the channel's default alias (the one used when a mention names none) and must be one of the channel's aliases. Repeatable `--family-default family=model-id` sets the team's model per family: checked against the catalog and saved through the server's own `PreferenceService` (`wiring.slack_services`, the one set for the Slack workspace) acting as the team principal, which creates the team key first when it is missing (so it needs `VAULT_KEYS` and `OPENROUTER_MANAGEMENT_KEY`; without it no key is created). `add` with `--family-default` provisions the team key before it writes the row, so a failed `add` can leave a key with no row: `openrouter_keys.py list` shows it and a retry reuses it. `--alias k=v` adds or replaces aliases (`v` is a brand or an exact model id) and cannot remove one. `add` takes `--daily-cap` and `--max-concurrent` from `SIDECAR_SLACK_DAILY_CAP_USD` and `SIDECAR_SLACK_MAX_CONCURRENT` in the environment the script runs in when they are omitted (`registry_defaults`, 4 and 3 when unset; the server itself doesn't read them). `update` changes only the options given; its label comes first, before the multi-value flags.
- `slack_usage.py`: `--team <label>` prints the same text as `@Sidecar usage` (`usage_report`, `usage_text`) from the team's key (`VAULT_KEYS`) and the job rows; names come from Slack when `SLACK_BOT_TOKEN` is set, else ids; entities are unescaped for the terminal.
- `rotate_secrets.py`: rotates a Railway service's secrets after a leak (macOS only). `--target sidecar` (default) covers this service: the OpenRouter management key, both Slack tokens and the admin client secret are pasted, and `VAULT_KEYS` (a new version label, with no old entry) and `LINK_SIGNING_KEY` are generated. `--target coach` covers `mpd-class-mcp`'s provider keys (OpenRouter, Tavily, Firecrawl, Resend, the MPD Interview Coach Slack bot). For each pasted key it waits for the operator to copy it, reads it with `pbpaste`, checks its prefix and clears the clipboard. After a typed `yes` it sets each with `railway variable set KEY --stdin --skip-deploys --project <id>`, so values never reach a command line, the screen or a deploy. It finds the project by name with `railway list`, so it runs from any folder. `--only NAME ...` limits the run.
- `slack_common.py`: what both Slack scripts share (environment, the key store, the Slack API, the model-default seeder, and `run_script`, which turns a known failure into one line on stderr).

**Invariants:** these reach the real Auth0 tenant, the deployed server or the OpenRouter management API, so a person runs them deliberately. They never print or log tokens or keys (management or student) and never call a paid model. Only `account_status` (probe) and the server create student keys, and `slack_channels.py` creates a team's key when it seeds model defaults. Nothing here ships in the package.

**Tests:** none by design. They are operator tools run by hand during acceptance (`docs/HOSTED_OPERATIONS.md`).

**Gotchas:** the token lives 10 minutes; delete `.dev-state/real-token` after use. If the browser already has an Auth0 session for another account (e.g. Google), run `real_login.py --prompt-login`.
